# Evaluation 介绍

> “怎么判断 AI 输出到底好不好”

这是 AI 工程最核心的问题之一。

因为 AI 不像传统程序：
```C#
1 + 1 == 2
```
AI 的输出是概率性的。

所以：

> 不能只看“能不能运行”

而要看：

* 是否稳定
* 是否正确
* 是否符合预期

# Evaluation 的本质

传统程序：
```
输入
→ 固定逻辑
→ 固定输出
```
AI：
```
输入
→ 概率推理
→ 非确定输出
```
所以必须建立：

> 评价体系

# AI Evaluation 常见类型

## 1. Correctness Evaluation（正确性评估）
判断：

> 答案对不对。

例如：
```
问题：
法国首都是什么

答案：
巴黎
```
这是正确性。

### Coding 场景

例如 Claude Code：
```
生成代码
→ 运行测试
→ 是否通过
```
测试通过：

* 说明正确性较高

这也是：

> AI Coding 最容易落地的原因。

因为代码能自动验证。

## 2. Relevance Evaluation（相关性评估）
尤其 RAG 常见。

判断：
```
检索结果
是否和问题相关
```
例如：

问题：
```
怎么配置 SQLite WAL
```
结果返回：

* Unity 动画系统

那就是低相关性。

## 3. Faithfulness（忠实性）
特别重要。

意思：

> AI 是否忠于给定上下文。

例如：

文档里没有：

> 支持离线支付

AI 却说：

> “系统支持离线支付”

这就是：

* 幻觉
* 不忠实

Faithfulness 是 RAG 的核心指标。

## 4. Latency（延迟）
AI 太慢也不行。

例如：

| 场景         | 可接受延迟 |
| :----------- | :--------- |
| 聊天         | 2~5 秒     |
| IDE 自动补全 | <500ms     |
| 语音对话     | <300ms     |

## 5. Cost Evaluation（成本评估）

例如：

> 一次请求 5 美分

一天百万请求：

> 公司直接爆炸。

所以很多工程优化：

* Prompt 压缩
* Chunk 优化
* KV Cache
* 小模型路由

本质都是：

> Cost Optimization(成本优化)

## 6. Human Evaluation（人工评估）

现在依然大量存在。

例如：

> 1~5 分

评价：

* 是否自然
* 是否专业
* 是否符合品牌语气

很多 AI 产品初期：

> 其实全靠人工打分。

# LLM-as-a-Judge

现在很流行。

意思：

> 让另一个 AI 来评估 AI

例如：
```
GPT-4
评价
DeepSeek 输出
```
或者：
```
Claude
评价
GPT 输出
```

示例
```
问题：
解释 CQRS

回答A：
...

回答B：
...

Judge:
请从：
- 准确性
- 清晰度
- 完整性
评分
```

# Evaluation 在工程中的位置

通常：
```
Prompt
→ 模型输出
→ Evaluation
→ 是否通过
```
比如：
```
生成 SQL
→ 执行测试
→ 不通过
→ 自动重试
```
这其实已经是：

> Agent Loop
